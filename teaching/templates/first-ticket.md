# Appendix G: The First Real Ticket
Use one bounded Ring Builder player-personalization step and its Markdown spec. You author the guidance, direct the agent and review its work. The agent creates/edits source, configuration and tests; this checklist is not a manual coding assignment.
Confirm that the account and application are approved for the code and data. Open the intended project and inspect existing changes.
Check the actual permission settings. Begin read-only and keep production credentials and customer data out of the exercise.
Ask the agent to inspect relevant files, explain the task, identify the existing pattern, and locate the validation command. Verify its references.
Ask the agent to start the existing application or run focused tests to establish a baseline, then review its evidence. Have it resolve in-scope setup failures before changing behavior.
Record the expected outcome, scope, checks, and approval boundaries. Use the spec structure in Appendix B when the task needs that detail.
Review one implementation step. Allow only the local edits and commands it requires, with no authority to push, deploy, or change external systems.
Inspect the returned diff and have the agent run the agreed checks after implementation. Include a relevant failure case and direct interaction when needed.
Accept the step, request a correction, or record why it remains open. Save the result and the next action outside chat.
Choose one recurring problem to address in the project guidance or checks. Try the correction on another task before making it a permanent rule.
The first loop is complete when you can explain the change, show how it meets the agreed behavior, and identify remaining checks. If only part of the feature is ready, save a handoff that lets the next session continue from that point.
